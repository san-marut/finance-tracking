# บันทึกประจำวัน (Finance & Workout Tracker PWA)

เว็บแอปแบบ PWA สำหรับบันทึกรายรับ-รายจ่ายและการออกกำลังกายส่วนตัว เขียนด้วย Angular 22 (standalone + signals, zoneless)
ข้อมูลทั้งหมดเก็บอยู่ใน `localStorage` ของเครื่องผู้ใช้ ไม่มีเซิร์ฟเวอร์และไม่ส่งข้อมูลออกไปที่ใด

## ฟีเจอร์

- **สองส่วนในแอปเดียว** — สลับระหว่าง "การเงิน" (สีคอรัล) กับ "ออกกำลังกาย" (สีเขียว) ได้จากแถบหัว
  แต่ละส่วนมีเมนูล่างและข้อมูลแยกกัน
- **บันทึกออกกำลังกาย** — เลือกประเภท (Cardio / Weight Training) → ส่วนของร่างกาย → ท่า
  แล้วใส่น้ำหนัก จำนวนเซต ครั้งต่อเซต และเวลาพัก (Cardio ใส่แค่นาที) ทุกท่ามีภาพลายเส้นประกอบ
  คัดลอกบันทึกของวันเป็นข้อความได้ รูปแบบ `[ประเภท] [ท่า] [น้ำหนัก] [เซต] [ครั้ง]` และ `[ประเภท] [ท่า cardio] [นาที]`
  เช่น `Weight Training Chest Press Machine 50 4 12` และ `Cardio Treadmill 20`
- **กรอกรายการเอง** ทั้งรายจ่ายและรายรับ พร้อมวันที่และบันทึกช่วยจำ
  ช่องจำนวนเงินพิมพ์เป็นสูตรได้ เช่น `120+35*2` และมีปุ่มบวกเร็ว +20/+50/+100/+500/+1000
- **แท็ก 2 ระดับ** — ระดับ 1 คือประเภทหลัก (อาหารและเครื่องดื่ม, เดินทาง, การลงทุน, ข้าวของเครื่องใช้ …)
  ระดับ 2 คือหมวดย่อยข้างใน (อาหารกลางวัน, น้ำมัน, กองทุนรวม …) แก้ไข/เพิ่ม/ลบได้เองทั้งหมด
  โดยแยกชุดแท็กของรายจ่ายและรายรับออกจากกัน
- **แดชบอร์ด**
  - ยอดคงเหลือ / รายรับ / รายจ่าย ต่อเดือน หรือดูรวมทั้งหมดตั้งแต่เริ่มใช้งาน
  - เทียบรายจ่ายกับเดือนก่อนหน้าเป็น %
  - โดนัทชาร์ตแยกตามแท็กระดับ 1 กดขยายเพื่อดูยอดแยกตามแท็กระดับ 2
  - กราฟแนวโน้มรายรับ-รายจ่ายย้อนหลัง 12 เดือน กดที่แท่งเพื่อกระโดดไปเดือนนั้น
- **หน้ารายการ** ค้นหา + กรองตามประเภท/แท็ก/เดือน พร้อมยอดสรุปของผลลัพธ์ที่กรอง
- **สำรองข้อมูล** ส่งออก JSON (กู้คืนได้) และ CSV (เปิดต่อใน Excel/Sheets) รวมถึงนำเข้าไฟล์สำรอง
- **PWA เต็มรูปแบบ** — ติดตั้งลงหน้าจอโฮมได้ ใช้งานออฟไลน์ผ่าน service worker
  มีปุ่มติดตั้งในแอปและแบนเนอร์แจ้งเมื่อมีเวอร์ชันใหม่

## เริ่มใช้งาน

```bash
npm install
```

รันโหมดพัฒนา (เปิดที่ http://localhost:4200)

```bash
npm start
```

> แนะนำ Node.js LTS (22 หรือ 24) — เวอร์ชันเลขคี่อย่าง 23 ใช้ได้แต่ Angular จะขึ้นคำเตือน

บิลด์สำหรับใช้งานจริง (ผลลัพธ์อยู่ที่ `dist/financetracker/browser`)

```bash
npm run build
```

service worker ทำงานเฉพาะบิลด์ production เท่านั้น ถ้าต้องการทดสอบ PWA จริงให้เสิร์ฟโฟลเดอร์ที่บิลด์แล้ว

```bash
npx serve dist/financetracker/browser
```

## Deploy ขึ้น GitHub Pages

มี workflow อยู่ที่ [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) — ทุกครั้งที่ push เข้า `main`
(หรือกดรันเองจากแท็บ Actions) จะบิลด์แล้ว deploy ให้อัตโนมัติ ได้เว็บที่
https://san-marut.github.io/finance-tracking/

ตั้งค่าครั้งเดียวก่อนใช้: ที่หน้า repo → **Settings → Pages → Build and deployment → Source: GitHub Actions**

สิ่งที่ workflow จัดการให้เป็นพิเศษสำหรับ Angular:

- บิลด์ด้วย `--base-href /finance-tracking/` เพราะเป็น project page ที่อยู่ใต้ path ย่อย
  (ค่า base href ดึงจากชื่อ repo อัตโนมัติ ถ้าเปลี่ยนชื่อ repo ก็ยังทำงานถูก)
- ก๊อป `index.html` เป็น `404.html` เพื่อให้เปิด URL ตรงๆ อย่าง `/finance-tracking/transactions` แล้ว router ทำงานได้
- สร้าง `.nojekyll` กัน Jekyll ตัดไฟล์ที่ขึ้นต้นด้วย `_`

ทดสอบบิลด์แบบเดียวกับที่ deploy ได้ในเครื่องด้วย

```bash
npm run build:pages
```

## โครงสร้างโค้ด

```
src/app/
  core/
    finance-store.ts   # signal store: รายการ, แท็ก, การคำนวณสรุปทั้งหมด, โหลด/เซฟ localStorage
    seed-data.ts       # แท็กเริ่มต้น 2 ระดับ + จานสี/ไอคอน
    utils.ts           # วันที่แบบไทย, จัดรูปแบบตัวเลข, ตัวคำนวณจำนวนเงิน
  models/
    finance.models.ts  # ชนิดข้อมูลกลาง (Transaction, Category, Summary, …)
  shared/              # คอมโพเนนต์ใช้ซ้ำ: โดนัทชาร์ต, กราฟแนวโน้ม, รายการรับ-จ่าย, ตัวเลือกเดือน
  pages/
    dashboard/         # สรุปรายเดือน/ทั้งหมด แยกตามแท็ก
    transactions/      # รายการทั้งหมด + ตัวกรอง
    entry/             # ฟอร์มเพิ่ม/แก้ไข/ลบรายการ
    categories/        # จัดการแท็ก 2 ระดับ
    settings/          # สำรอง/นำเข้า/ล้างข้อมูล
```

ไอคอนแอปวาดเป็น SVG เอง ต้นฉบับอยู่ที่ `public/icons/icon.svg` (แบบมุมโค้งสำหรับใช้ทั่วไป)
และ `public/icons/icon-maskable.svg` (แบบเต็มขอบสำหรับ maskable ของ Android)
ไฟล์ PNG ทุกขนาด, `apple-touch-icon.png` และ `favicon.ico` เรนเดอร์มาจาก SVG สองไฟล์นี้

การคำนวณสรุปทุกอย่างเป็น `computed()` บน signal ของรายการดิบ จึงอัปเดตทันทีเมื่อมีการเพิ่ม/แก้ไขข้อมูล
และมี `effect()` ตัวเดียวที่คอยเขียนข้อมูลลง `localStorage` (คีย์ `finance-tracker.v1`)
